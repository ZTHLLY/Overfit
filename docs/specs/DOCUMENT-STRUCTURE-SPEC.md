> 文档版本：0.2 · 日期：2026-10-06 · 状态：**核心已实现并通过独立离线工程验收；真实 PDF 留出/语义校准未完成**。

本规范定义跨页文档结构、来源追溯和引用定位容差的目标行为。新运行契约冻结于第 9 节，历史记录不重新解释。旧协议见 [judge-v3 历史契约](/Users/silver/Documents/github/Overfit/docs/specs/EVAL-JUDGE-SPEC.md) 的既有运行事实。总体目标见 [EVALUATION.md](/Users/silver/Documents/github/Overfit/docs/EVALUATION.md)；后续实施顺序见 [DOCUMENT-STRUCTURE-PLAN.md](/Users/silver/Documents/github/Overfit/docs/plans/DOCUMENT-STRUCTURE-PLAN.md)，实施证据单独回填。

## 1 目标与原则

以**语义完整、可追溯、容忍合理版面边界差异**为目标，而不是让页码或逐字摘录成为语义裁判。

- 不针对 `clustering.pdf`、特定页码、课程关键词、某道题或某个模型响应增加特判。
- chunk 可以跨物理页；不为满足单页校验而强制逐页拆分，避免割裂标题、否定句、表格或图文关系。
- 同一 PDF 的引用定位允许围绕固定锚点前后各 1 个物理页；它是定位容差，不是逻辑支持的豁免。
- 程序保存输入、来源、选择过程和预算诊断；judge 判断语义；有实质不确定或矛盾时交人工，不由代码最终批准内容。
- 不要求完美字符对齐、精确 quote 或用户重做全量人工标注。已有来源信息不能丢失，缺失部分明确 unknown。

## 2 术语与当前边界

| 概念 | 目标定义 |
| --- | --- |
| 物理页 | PDF 页序，1-based；不等同印刷页码、幻灯片编号或 OCR 中的数字 |
| 引用锚点 `a` | 进入本次定位政策前冻结的声明页码；后续找到证据不得移动它继续扩展 |
| 文档版本 | 同一 PDF 的可追溯身份及正文/文件摘要，不只比较 basename |
| 原生成材料 | `original_generation_context`，当时实际发送给生成模型的材料快照 |
| 补充引用材料 | `supplemental_review_context`，评审时另行取得、仅辅助引用定位的材料 |
| provenance | 已知的文档、物理页、片段、字符 span、bbox、图像/表格关联等来源信息 |

generator 的 ±2 页引用修复、PR1 严格 source/page diagnostics 和 golden 严格页指标保持独立、不改变含义。judge-v3 的具体页/跨页处理作为历史事实保留；新运行采用第 9 节冻结的 judge-v4 / citation-window-v1，不将历史 v3 报告改称 v4。

若 trace 同时保存生成原引用和修复后引用，必须分别标识；新政策针对哪份声明引用必须在新记录中明确，不能把修复后页码冒称原生成页码。每一份被审查的声明引用都先冻结其自身锚点，再应用一次窗口。

## 3 固定 ±1 页窗口

文档真实物理页数为 `P`、有效锚点为 `a` 时，窗口固定为：

```text
W = [max(1, a - 1), min(P, a + 1)]
```

1. 只允许同一文档版本，不跨 PDF，不因内容相似而换文件。
2. 窗口仅从原冻结锚点计算一次；找到邻页证据不移动锚点，不把 ±1 连续扩成 ±2、±3。
3. 外部可展示“47”或“47–48”等定位形式；显示范围不得反过来变成新的扩窗依据。
4. 文档页数未知或锚点无效时记录 unknown/来源诊断，不猜页数、钳制非法锚点或声称已完成合法窗口核对。
5. 大 chunk 的范围与 W 有交集，不等于其中全部正文都属于 W，更不等于引用支持。不能让 1–100 页的 chunk 因碰到 47 页就自动通过。
6. 已知 provenance 能区分时，记录真正用于窗口内定位的片段及来源；无法区分时如实说明粒度限制，不能伪造窗口内精确证据。

位于 W 的上下文只代表可用于新政策的引用定位检查。**题干、答案论断、否定范围、表格行列归属或图注语义是否被支持，仍由 judge 判断。** 同页也可能不支持，邻页也可能支持；页码距离不能替代语义关系。

## 4 跨页语义结构与 provenance

不强制一个 chunk 对应一页。解析/清理/chunking 的未来调整应保留必要语义关系，例如：

- 标题和紧接正文、句子跨页、列表前提与后续条目、否定词与被否定内容；
- 表头与跨页续表、行列对应、脚注、单位、条件限制；
- 图像或示意图与图注、正文解释及提问所需上下文。

内部允许一个逻辑片段关联多个来源片段，保留已知物理页、字符 span、bbox、图像/表格引用和相应提取信息。不能为输出单一 page 字段而丢掉其余已知来源，也不能把整个跨页片段强行归到第一页。

这些是可逐步实现的来源能力，不要求每份 PDF 都产出完美 bbox 或逐字页边界。没有的信息明确 unknown；推断的位置与提取器直接给出的位置应可区分。不能凭模型补写看似精确的 provenance。

多页内容仍可保留为一个 chunk，对外只展示单页锚点；内部保存完整已知来源不意味着必须拆分、重写正文或重建索引。外部简洁引用与内部多来源可以并存。用户可以看到锚点或短页范围，审计记录则保存实际已知的多个来源及限制。图片/表格无法从纯文本可靠恢复时，不因文本中出现相关关键词就认定关系完整。

## 5 原生成材料与补充引用上下文隔离

本规范允许未来显式加入邻页辅助上下文，但不授权任何隐式 PDF 读取、重解析、API 请求或模型加载。

- `original_generation_context` 必须保持原 trace 内容、顺序和实际发送范围，不用后补片段覆盖它。
- `supplemental_review_context` 单独记录，必须标明生成当时没有这些材料；只辅助引用核验，不能重新定义原材料是否支持答案或足以作答。
- 原材料的 material_support 和 answerability 只能依据原材料评审。若原材料不足而邻页补足，只能表述“原输入不足；补充上下文发现引用附近有相关依据”，不能洗成“原输入已支持/可作答”。
- 请求和输出范围须显式区分：answerability 的原输入评审不混入补充上下文；citation 的补充复核不得反向污染同次或后续原材料结论。是否拆为独立请求由后续实现规范确定，但不得靠一段含混提示词掩盖输入范围差异。
- 没有补充材料就明确未提供，不从文件路径、索引或网络默默补齐。材料缺失和检索/预算不足不伪装成内容负判。

为保证可复查，每次显式选择补充上下文至少保存：文档版本、锚点与固定窗口、真实物理页信息、选择的片段/顺序/理由、输入预算与是否受限、正文 hash、实际发送正文及必要图文内容身份。保存失败不得一边丢失记录一边继续调用。

大 chunk 不能借窗口交集整块成为“窗口内证据”。若为了语义完整保留窗口外关系，应另行标注其范围和用途，不能计作窗口内定位支持或无限扩窗。选择必须受显式预算约束，不能静默截掉否定、表头或关键条件后仍称语义完整；确有缺口时保留限制并交 judge 表达不确定。

## 6 技术、语义与人工职责

新政策下，**仅仅跨页，或证据在同文档固定 ±1 窗口内的定位偏差，不单独触发人工复核**。它们可保留为来源/粒度注释，而不是评审失败。

这不取消其他实质疑点：未知/部分支持、总分项矛盾、文档身份不一致、页码非法、来源无法核实、必要材料或语义关系缺失等仍需明确记录；按对应不确定性进入人工流程。无法定位精确 quote 本身仍是辅助诊断，不代替语义裁决。跨页本身与“现有证据无法判断具体论断”须区别。

程序不因 W 内命中而自动给 supported，也不因超窗而擅自改写模型原判。超窗/错文件不能称符合新定位政策；保留原模型意见并显示实际范围和来源疑点，必要时待人工。模型清晰负判也不因为位置符合容差而转正。

## 7 版本、回放与历史保全

- 新政策、prompt、上下文选择逻辑及实际输入发生变化时，必须有独立可辨认身份和新结果目录；具体运行协议名留待实现冻结，不虚构已存在的新 CLI 或配置键。
- 历史 trace、judge 和 challenge 输出只读保留。旧规则产生的严格 diagnostics 是历史事实，不能修改原文件把过去跨页待审变成新政策通过。
- 原实现的 PR1 严格诊断可以与未来弹性定位结果并存，但名称、范围和政策身份必须区分；不能把严格页检查结果偷偷重命名为 ±1 检查。
- replay 只读取记录材料，不读取 PDF、联网补页或加载模型；新实现若不兼容旧协议，应明确拒绝，不能静默用新语义复算旧运行。
- golden 严格页命中、Recall 等指标不默改为 ±1；若未来增加宽松定位指标，必须另命名、另报分母和版本，不混成旧指标改善。
- 本轮不改 generator ±2 修复、.env、现有 CLI 用法、原有索引或原始数据。已授权核心代码实现；P5 补充引用仍须另行批准。

## 8 验收要求（工程与真实质量分开记录）

| 边界 | 应覆盖的正例与反例 |
| --- | --- |
| 窗口 | 相邻 ±1 可用于定位，±2 不符合；首尾页裁剪、非法锚点、未知总页数、不同文件同页码 |
| 固定锚点 | 邻页命中不能滚动扩窗；显示页范围不扩窗；巨大跨页 chunk 不能仅凭相交通过 |
| 语义完整 | 跨页正文/否定/前提保留；表头、续表行列、单位和脚注不丢；图文及图注关系保留 |
| 多来源 | 多个已知 page/span/bbox 不丢失、不压成第一页；缺 provenance 标 unknown，不伪造精度 |
| 分层职责 | 仅跨页/容差偏差不单独人工；模型 unknown/partial/矛盾仍待审；位置命中不自动正判 |
| 输入隔离 | 补充上下文不能把原输入 unsupported/not_answerable 改写成原输入已支持；实际发送范围可审计 |
| 记录与预算 | 版本/窗口/选材/预算/正文 hash/实际输入齐备；超预算不静默截断关键关系，失败不继续无记录调用 |
| 历史兼容 | 旧 trace/judge/golden/±2 行为不改写；不同政策结果不混用；离线 replay 不获取新材料 |
| 泛化 | 使用异质、未参与调参的 PDF 验证，而非只靠 clustering.pdf 或单个课程案例；负例同样保留 |

这些验收检查已有可获信息是否保留及限制是否诚实，不把完美版面恢复、全部公式 OCR 或所有图表理解作为本次容差政策的前置条件；无法可靠提取的内容应保留来源与不确定性。

单份 PDF 的改善不能证明普遍正确。验收可使用合成边界、现有公开/授权材料和少量争议抽查，不要求用户重新全量标注 golden。工程测试通过只能证明约定边界，真实语义质量仍需独立校准；本轮仅运行离线工程测试，不运行真实模型。

## 9 本次核心实现的冻结契约

用户已授权编码；本节已通过 P0 独立评审，用于实施 P1～P3。P5 邻页补充不在本次实现范围。

- **来源结构**：`Page`、`ParsedDocument`、`Chunk` 在现有字段之后增加可选 `provenance`，旧对象缺失为 `None`。独立来源 schema 为 `1`，对象字段固定为 `schema_version`、`document_sha256`（SHA-256 或 null）、`page_count`（可信物理总页数或 null）、`extractor`（提取器与版本或 null）、`blocks`。文档版本与提取策略身份不混用。
- **块结构**：每块固定 `block_id`、`label`、`parent_id`、`context_id`、`text`、`locations`、`text_span`、`block_span`、`mapping`。可选父节点/图片上下文及 span 缺失为 null。`mapping` 为 `exact` 或 `coarse`；span 是半开区间。每个 location 为 `page`、`charspan`、`bbox`；bbox 有 `l/t/r/b/coord_origin`，未知时 null，数值须有限。
- **坐标意义**：`text_span` 对应当前 Page/Chunk 文本，`block_span` 对应保留的原块 `text`。exact 要求两段文字相等；清洗后不能可靠映射则降为 coarse，不伪造精度。location 的 charspan/bbox 保留提取器提供的原坐标，不能把表格 Markdown 的索引冒充原坐标。未进入实际 chunk 文本的原块正文只用于审计，不成为生成或 judge 的额外依据。
- **严格 JSON 类型**：上述顶层和块/location/bbox 字段全部必需，未知键拒绝；仅明确 nullable 的字段可为 null。`schema_version` 为整数 1；`page_count`/`page` 为正整数且不接受 bool，已知总页数时 location.page 不得超过它；所有 span 是两个非负、非递减整数的 JSON 数组（非 bool）。`document_sha256` 是 64 位十六进制字符串或 null，`extractor` 是非空提取器/版本字符串或 null；`blocks`/`locations` 为数组。`block_id`/`label` 是非空字符串，`parent_id`/`context_id` 是非空字符串或 null，`text` 是字符串，`coord_origin` 是非空字符串。`text_span`/`block_span` 可 null；exact 时两者必须存在，分别验证当前容器/原块范围并验证子串相等。location.charspan 仅验证非负有序整数，不以导出的 table Markdown 长度约束。ParsedDocument 没有拼接 text：其块的 text_span 固定 null，不沿用局部 Page offset；Page/Chunk 再绑定各自坐标。
- **公共验证接口**：`overfit.provenance.validate_provenance(value, *, text=None)` 严格校验结构、类型与可核对的范围，返回深拷贝；不自动补写未知字段。`provenance_pages(value)` 返回已知 locations 的物理页集合。内存构造和存储/记录边界均校验。
- **可信身份取得**：仅在原本显式的 parser 调用中对源文件计算 SHA-256；pypdf reader 的页数或 Docling `ConversionResult.input.page_count` 可提供真实物理页数。仅有部分 `document.pages` 或最高已见页不推断总页数。无法取得则 unknown；judge/replay 不补读 PDF。
- **锚点**：正式生成评审固定 `post_policy` 最终引用，标记 `anchor_origin=post_policy`；challenge 固定输入引用，标记 `anchor_origin=challenge_input`。原 pre_policy 和 ±2 修复记录保留；不将最终引用的 ±1 冒称相对原引用的总误差也只有 ±1。
- **引用身份**：同 source 的唯一已知文档 SHA 和可信总页数才能完整验证窗口；已知版本或页数冲突为来源疑点，不能挑最有利的一份。仅缺历史 metadata 或无法逐字定位时记录 `unverified` 诊断，不虚构合法窗口，也不因跨页本身单独转人工；错文件、未知 chunk、明确超窗、来源冲突及模型不确定/矛盾仍保留复核原因。
- **窗口诊断边界**：只从实际承载 chunk.text 的映射块取得候选来源页；audit-only、已清掉或无法确定与选中文字关系的块不得为窗口验证提供证据。已知相关页全在 W 才可定位 verified，全在 W 外为来源疑点；部分相交且无法精确缩到可证明的页集为 unverified/info，不将交集当通过。coarse 若有可确认承载当前文字的范围且全部可能页在 W，可做页级 verified；否则诚实 unverified。不存在 quote 不强制 pending，任何定位 verified 均不代表语义 supported。
- **版本**：新写入 trace envelope 为 `2`，材料 schema 为 `2`；读历史 trace `1` 时保留原数据和严格引用语义，缺 provenance 为未知。judge 新运行使用 `judge-v4`、记录 schema `4`、定位政策 `citation-window-v1`。旧 judge-v3 回放由不匹配实现明确拒绝，不重新解释或覆盖原输出。challenge 新运行使用 `challenge-v2`、记录 schema `2` 与 judge-v4；旧 suite 输入 v1 可读取但无新增来源，新增来源使用显式 suite 输入/annotations v2。旧 suite 原字节与设计标注隔离保持。v1 入口保持原 strict membership 校验；v2 要求输入页为正整数且有同 source 材料，但不以旧页 membership 阻断 ±1 邻页案例，已知非法锚点/超窗由新政策诊断，strict 结果另列。
- **模型输入隔离**：只传原实际 chunk.text；可以附不含原块正文的来源标签/位置映射，但不能把 provenance 中被清洗或未选中部分的 block.text 发送给生成/评审模型。answerability 仍不含答案或引用。metadata 不是补充正文，P5 仍未实现。
- **存储与缓存**：新索引 schema `2` 保存 provenance JSON 和每文档处理身份。schema `1` 索引仅允许兼容读取为来源未知，不在打开时自动迁移或修改；写旧索引明确拒绝并提示使用隔离新索引。新缓存同时检查源 hash 与处理 fingerprint（backend、依赖版本、parser/cleaner/chunker/provenance 实现身份和 chunk 参数），不再只按源 hash 跳过。已有 backend/embedding/chunk profile 核验保持。为避免只读 SQLite 仍创建 WAL/SHM，旧索引经校验的临时只读快照读取；原目录不产生 sidecar。当前打开任意已有索引若有非空 WAL 则明确拒绝，要求关闭 writer 并显式 checkpoint 后再开；此限制也适用于 schema2，不宣称保留活跃 WAL 并发打开能力。
- **验证边界**：先运行现有离线测试作为基线，保全既有 outputs/index/eval/依赖和配置。开发使用合成正文、跨页表格、图片子节点、多来源及缺失 metadata；独立 reviewer 使用未参与作者调试的不同页号/内容/结构组合。真实异质 PDF 留出与在线语义校准另列未完成，不将假提取器测试当真实解析质量证明。任何本地试验索引只在 pytest 临时目录创建，使用假向量，不请求 embedding。
